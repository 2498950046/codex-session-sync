# 宝库、快照预览与可携带宝藏实施计划

## 简要计划

1. 统一快照创建入口，点击后明确选择“完整快照”或“选择快照”；两者都只保存在本地，不提供直接 Push。
2. 在“同步 → 快照与恢复”中支持本地快照显示名称修改，并为本地快照、远端 Revision 和宝藏复用同一套只读会话预览组件；远端 Revision 不支持重命名。
3. 新增左侧“宝库”页面：一级页按时间倒序展示独立宝藏，二级页提供临时快照组合预览、宝库信息和本地快照拖放区。
4. 拖放只维护当前页面内的临时预览草稿，不固定或保护来源快照；预览阶段检测并标记同 UUID 多版本，但不强制立即解决。
5. 点击“导出为宝藏”时重新校验来源并完成冲突选择，将当前内容区导出为物理自包含、可直接分享的完整快照包。
6. 接收方导入宝藏后，将其作为普通本地完整快照注册，直接复用现有快照预览和恢复流程。

## 详细实施计划

### 一、已确认的产品语义

#### 1. 快照

- “完整快照”包含当前 Codex Home 扫描到的全部受支持会话。
- “选择快照”允许按活动/归档、项目和会话任意选择内容，不要求这些会话相对当前 Tracking 有变化。
- 完整快照和选择快照都只写入本地快照库，不允许从快照详情直接 Push 到远端。
- 快照内容及 Snapshot ID 保持不可变；“重命名”只修改本地 `SnapshotMetadata.description` 等展示元数据，不改变内容哈希。
- 远端 Revision 不支持重命名，也不维护本机别名。

#### 2. 临时组合预览

- 宝库二级页面右下角展示本地快照，拖入主内容区后加入当前内存中的临时预览草稿。
- 拖放不复制数据、不固定快照、不增加 GC 保护，也不持久化草稿。页面刷新、应用退出或来源快照被删除后，预览允许失效。
- 主内容区只用于查看拟组合的会话，不写入 Codex Home、不修改远端、不建立 Tracking。
- 主内容区可包含一个或多个来源快照。不同 UUID 自动并列显示；同 UUID 且语义内容相同在预览中折叠为一项；同 UUID 且内容不同显示“多个版本”冲突标记和来源信息。
- 预览阶段不静默选边，也不要求用户立刻解决冲突。用户可以移除来源快照、查看各版本或继续调整组合。

#### 3. 宝藏

- 宝藏是一个物理自包含、可携带、可分享的完整快照，不是指向普通快照或本机对象库的引用集合。
- 即使普通快照、本地内容寻址对象库、远端服务器及其他应用数据全部丢失，只要宝藏文件仍在且未损坏，就能独立查看并恢复其中内容。
- 宝藏内部必须包含快照 Manifest、全部线程语义模型、全部 rollout 内容、受支持附件和恢复所需的 SQLite 线程/子记录语义数据，以及每个对象的 SHA-256 和字节长度。
- 宝藏不包含 `auth.json`、API Key、配置、插件、技能、MCP、日志、工作树、源码或发送方机器的绝对路径。
- 宝藏导出结果在语义上标记为完整快照；这里的“完整”表示对当前内容区最终组合结果自包含。恢复时按现有完整快照恢复语义处理，因此可能替换接收方当前会话，必须沿用现有 Codex 关闭检查及“是否保留恢复备份”的明确选择。
- 宝藏文件名只用于人类识别；内部使用稳定 UUID 和 Manifest hash 标识，重命名外部文件不改变其内容身份。

### 二、当前行为

- `sync-core` 已支持不可变本地 Snapshot、内容对象、SHA-256 校验、`SnapshotMetadata`、完整/选择 scope、快照列表、回收站和恢复。
- 当前“选择会话创建快照”复用了同步 Staging Plan，主要面向相对 Tracking 的变更，不等同于从当前 Codex Home 任意选择重要会话。
- 本地快照元数据已有 `description`，后端已有更新元数据命令，但前端快照详情尚未形成完整的重命名交互。
- 当前会话浏览和消息查看面向实时 Codex Home；快照历史列表主要展示摘要，尚缺直接从 Snapshot/Revision 对象读取消息的统一只读预览 API。
- 远端 Revision 可下载为本地快照，也可恢复；本计划不增加远端重命名。
- 当前没有宝库索引、临时组合预览状态或物理自包含的宝藏文件格式。

### 三、目标架构

#### 1. 领域模型

新增或明确以下模型边界：

```text
LocalSnapshot
  ├─ Full：当前 Home 的完整状态
  └─ Selection：用户任意选择的一组会话

TreasureDraft（仅前端内存）
  ├─ sourceSnapshotIds[]
  ├─ detectedThreads[]
  └─ detectedConflicts[]

TreasurePackage（物理独立）
  ├─ package.json / header
  ├─ snapshot manifest
  ├─ thread descriptors
  ├─ rollout/attachment objects
  └─ integrity index
```

`TreasureDraft` 不进入 Tracking、不写数据库、不构成可靠持久状态。`TreasurePackage` 是导出后的权威数据，不能依赖 `sourceSnapshotIds` 继续存在。

#### 2. 宝藏文件格式

定义带版本号的单文件扩展名，例如 `.codex-treasure`。格式需要满足：

- 跨 Windows、macOS、Linux 可读写；路径统一使用包内逻辑路径和 `/` 分隔符。
- 包头包含 schema version、宝藏 UUID、显示名称、创建时间、线程数量、逻辑字节数及 Manifest hash。
- 所有对象随包携带；允许包内按内容哈希去重，但禁止引用包外对象。
- Manifest 递归规范化并校验 SHA-256；对象条目同时校验类型、哈希和字节长度。
- 导出写入同目录临时文件，完成全量校验后原子替换最终文件；失败或取消清理临时文件。
- 导入时限制 Manifest 大小、对象数量、单对象与总解包大小，拒绝重复冲突条目、路径穿越、绝对路径、符号链接和解压炸弹。
- 首版不实现加密、数字签名和云端宝库；这些作为后续范围。界面应提示宝藏可能包含敏感对话内容。

#### 3. 物理独立与本地对象复用

- 导出必须从已校验的源对象读取实际字节并写入宝藏包，不能只写哈希引用。
- 宝藏包自身始终独立；导出完成后删除源快照或清空普通对象库不影响宝藏。
- 接收方导入时可以把包内对象复制并校验到其普通本地对象库，以复用现有 Snapshot 恢复代码。导入后的普通本地快照可以使用本机内容去重，但原始宝藏文件仍是独立恢复源。
- 宝库列表的每一项对应一个实际宝藏包。索引只保存位置、名称和校验摘要；索引丢失时应能通过重新扫描宝藏目录重建。

### 四、冲突与导出时机

采用“预览时检测，导出时裁决并重新校验”的规则。

#### 预览阶段

- 读取各来源快照的线程描述符并按 UUID 分组。
- 不同 UUID 自动组成预览集合。
- 同 UUID、语义 hash 相同的内容折叠展示。
- 同 UUID、语义 hash 不同的内容保留全部候选版本，并显示冲突数量、来源快照名称、更新时间和摘要。
- 允许用户在预览阶段提前选择版本，但选择只是草稿状态，不具有持久性或最终效力。

#### 导出阶段

1. 重新载入所有来源 Snapshot Manifest，确认它们仍存在且格式受支持。
2. 校验 Manifest、线程描述符、rollout 和附件对象的哈希及长度。
3. 根据重新计算的 UUID/hash 集合校验预览是否过期；有变化则中止导出并要求刷新预览。
4. 对不同 UUID 和相同内容自动合并；对每个同 UUID 不同内容要求明确选择一个候选版本。
5. 拒绝缺失、重复、未知或与最新冲突指纹不匹配的选择。
6. 生成唯一、排序稳定的最终线程集合，写成新的完整 Snapshot Manifest。
7. 将最终 Manifest 和全部实际对象复制到临时宝藏包，进行一次闭包完整性校验后原子安装。

宝藏导出不改变来源快照、Codex Home、Tracking 或远端 Head。

### 五、界面设计

#### 1. 快照创建入口

点击“创建快照”先打开模式选择：

- “创建完整快照”：显示当前 Home 会话数量与预计逻辑大小，确认后执行现有完整快照流程。
- “选择会话创建快照”：进入公共会话选择器，可按活动/归档、项目、会话筛选和勾选；确认后创建独立 Selection Snapshot。

抽取 `ThreadSelectionDialog`，由选择快照和“选择并推送”共同复用。数据源和候选规则通过 props/adapter 区分：选择快照提供全部可用会话，选择 Push 仍只提供相对 Tracking 的变更。

#### 2. 快照与恢复

- 本地快照详情增加“重命名”，只更新展示元数据。
- 本地快照增加“预览会话”；远端 Revision 增加“预览会话”，但不显示重命名操作。
- 抽取 `ReadOnlySessionBrowser`、`ThreadMessageViewer` 和 `SnapshotPreviewPanel`，统一项目分组、分页、会话摘要和消息渲染。
- 预览 API 接受明确来源类型和 ID，不直接接受任意文件路径；后端重新解析并校验来源，避免前端越权读取。

#### 3. 宝库一级页

- 左侧主导航新增“宝库”。
- 一级页按 `createdAt` 倒序展示宝藏名称、创建时间、会话数量、逻辑大小、文件大小和最近一次校验状态。
- “新建宝库”按已确认交互保留，但首版将其解释为创建一个临时宝藏编辑页面：输入宝藏名称后进入二级页；在真正导出前不创建可靠数据包。
- 支持打开、重命名、导出文件副本、验证和删除宝藏。删除必须展示精确文件路径并二次确认，因为宝藏可能是唯一剩余副本。

#### 4. 宝库二级页

- 主内容区：临时组合后的只读会话树、消息预览及冲突标记。
- 右上：当前草稿名称、来源快照数量、预览会话数、冲突数和“导出为宝藏”按钮。
- 右下：本地快照列表，支持搜索、完整/选择过滤和拖入主内容区。
- 拖放应提供等价的“添加到预览”按钮及键盘操作，兼容 WebView 差异和无障碍场景。
- 来源快照被删除或变更时，预览显示失效项；不自动固定、不阻止 GC。点击导出时以重新校验结果为准。

### 六、后端与持久化边界

#### sync-core

- 增加独立于同步 Staging 的任意线程选择快照构建函数。
- 增加按 Snapshot Manifest 读取线程列表和消息页的只读接口。
- 增加纯函数式 Treasure 合成规划：UUID 分组、语义 hash 去重、冲突指纹、显式 resolution 和最终线程排序。
- 增加宝藏包写入、读取、校验、导入注册和目录重建能力；核心层不依赖 Tauri 或 HTTP。

#### Tauri 桌面后端

- 增加快照模式创建、快照预览、远端 Revision 只读预览、宝藏导出/导入/验证/列表/重命名/删除命令。
- 长时间的对象复制、校验和导入使用现有后台任务、进度、取消和仓库租约。
- 只读预览使用仓库共享租约；导出、导入、删除宝藏和快照元数据更新使用仓库独占租约。
- 只有恢复到 Codex Home 时获取每 Home 写租约并要求 Codex 完全关闭；创建/导出本地快照仍遵循当前产品边界的关闭检查。

#### 前端

- 将当前集中在 `SessionSyncApp.tsx` 的会话浏览、版本卡片、消息查看与选择器逐步拆分为公共组件，避免宝库页面复制交互逻辑。
- 路由新增 `/vault` 和 `/vault/new`（或带草稿 ID 的二级路径）；临时草稿默认仅存 React state。
- 拖放 payload 只携带内部 snapshot ID，不暴露本地 Manifest 路径。

#### 远端服务

- 本计划不修改远端协议，不上传宝藏，不为 Revision 增加名称或别名。
- 远端 Revision 预览沿用现有鉴权下载与对象校验边界；可使用受限缓存，但不得改变远端 Head。

### 七、实施阶段

#### 阶段 A：快照创建与元数据体验

- 抽取公共 `ThreadSelectionDialog`。
- 将快照按钮改成完整/选择两种明确入口。
- 让选择快照脱离 Tracking 变更计划，支持任意会话选择。
- 增加本地快照重命名交互和输入校验。
- 测试完整/选择 scope、空选择、重复 UUID、快照元数据不改变内容身份。

#### 阶段 B：统一只读预览

- 实现本地 Snapshot 消息读取接口和预览组件。
- 实现远端 Revision 的只读预览数据源，不增加远端重命名。
- 复用会话树、分页和消息展示；验证预览不写 Codex Home、Tracking 或远端。

#### 阶段 C：宝库页面与临时组合

- 增加左侧入口、一级列表和二级布局。
- 实现快照拖放/按钮添加、来源移除、临时组合和冲突标记。
- 实现预览 fingerprint，以便导出时检测来源变化。
- 不实现自动固定、来源保护或草稿持久化。

#### 阶段 D：物理独立宝藏包

- 冻结 `.codex-treasure` v1 schema 和跨平台路径规则。
- 实现导出规划、冲突 resolution、对象闭包收集、临时写入、全量校验和原子安装。
- 实现宝藏目录扫描与可重建索引，确保删除普通快照和对象库后仍可单独验证宝藏。
- 增加导出敏感内容提示；加密留待后续。

#### 阶段 E：接收、查看与恢复复用

- 实现“导入宝藏为本地快照”：校验包后复制对象并注册完整 Snapshot。
- 导入后直接出现在现有“快照与恢复”列表，复用重命名、预览和恢复按钮。
- 恢复继续使用现有本地 Snapshot checkout，不新增宝藏专用写入路径。
- 恢复前要求 Codex 关闭，并明确选择是否保留可恢复备份。

### 八、兼容性与迁移

- 现有完整和选择快照继续可列出、预览和恢复；新增元数据字段使用 serde 默认值保持向后兼容。
- Treasure schema 独立版本化，旧客户端遇到更高版本时只能报告“不支持”，不能尝试恢复。
- 规范化语义版本必须写入包中；接收方只接受其明确支持的版本。
- 远端协议保持 v4，不因宝藏功能升级。
- Windows、macOS、Linux 需测试 Unicode 名称、长路径、大小写差异、原子替换和跨平台传输后的读取。

### 九、破坏性操作与安全规则

- 预览、重命名和导出不修改 Codex Home。
- 宝藏删除是真正的数据删除，必须二次确认并提示宝藏可能是唯一副本；优先移入宝库回收站，永久清理另设动作。
- 宝藏恢复沿用本地替换规则：用户必须明确选择是否保留恢复备份；选择“不保留”后，成功操作可以永久丢弃原本地状态。
- 从外部接收的宝藏一律视为不可信输入，在任何注册或预览前完成结构、路径、数量、大小、哈希和 schema 校验。
- 不从包中执行脚本、不创建包内声明的任意绝对路径、不恢复发送方工作区源码。

### 十、测试与验证

#### 核心单元测试

- 任意会话选择快照与完整快照的范围正确。
- 相同 UUID/hash 去重、同 UUID/不同 hash 冲突、选择缺失与过期 fingerprint 拒绝。
- 宝藏对象闭包完整，删除所有来源快照和普通对象副本后仍能从宝藏读取、验证和导入。
- 缺失对象、篡改内容、错误长度、重复条目、路径穿越、绝对路径、符号链接和超限包被拒绝。
- 宝藏内容不包含 API Key、本机绝对路径和不允许同步的配置。

#### 集成测试

- 创建完整/选择快照 → 临时组合预览 → 冲突选择 → 导出宝藏。
- 将宝藏复制到全新临时仓库 → 导入为本地快照 → 预览消息 → 使用现有恢复路径写入临时 Codex Home。
- 导出后删除来源快照并运行普通对象 GC，宝藏仍可独立完成上一步。
- 导出期间取消或失败不留下可见的半成品文件。
- 恢复备份选择“是/否”两条路径均符合现有 Journal 和 Tracking 约束。

#### 前端测试

- 快照模式选择、任意会话勾选、本地快照重命名。
- 本地/远端/宝藏使用同一预览组件并保持只读。
- 拖放和按钮添加等价，失效来源提示正确，冲突未解决时禁用导出。
- 宝库一级列表按时间倒序，二级布局在桌面和窄屏下可用。

### 十一、验收标准

- 点击创建快照时能明确选择完整或任意会话快照，且不会产生远端 Push。
- 本地快照可改显示名称；远端 Revision 无重命名入口。
- 本地快照、远端 Revision 和宝藏均能通过公共只读组件预览线程与消息。
- 宝库二级页支持将本地快照临时加入内容区，不固定、不保护、不持久化来源引用。
- 预览能标记同 UUID 多版本；导出前必须重新校验并解决全部冲突。
- 每个宝藏都是物理自包含的完整快照包，可作为单文件发送给其他人。
- 来源快照、普通对象库和远端全部不可用时，未损坏的宝藏仍可独立验证、查看并导入。
- 接收方导入后，宝藏作为普通本地完整快照出现，并直接复用现有快照恢复功能。
- 实施不修改远端协议、远端 Revision 名称或命名空间 Head。

### 十二、明确延期范围

- 宝藏加密、数字签名和可信发布者校验。
- 宝藏云端同步、远端分享链接和多人权限。
- 临时组合草稿的跨重启保存与协作编辑。
- 宝藏之间的增量包、补丁包或外部对象引用。
- 在不导入为本地快照的情况下直接写入 Codex Home。
