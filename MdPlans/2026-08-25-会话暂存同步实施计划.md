# 会话暂存快照与选择 Push 实施计划

日期：2026-08-25

## 简要计划

1. 建立工作区、已同步基准、变更计划和暂存区四层模型。
2. 复用会话浏览，新增快照和 Push 共用的多选暂存弹窗。
3. 默认只展示变化，支持全选、项目/会话多选、跨分页选择和待删除项。
4. 支持完整快照与选择快照，并为选择快照提供增量恢复和明确警告的精确恢复。
5. 将所选变更与远端完整树合成为完整 Revision，再通过现有 CAS 和冲突流程 Push。
6. 覆盖差异、选择、删除、恢复、合成 Push、冲突和性能的自动化测试。

## 详细实施计划

### 1. 当前状态与目标

当前扫描只读取 rollout 首条元数据和线程数据库摘要，保持快速。当前快照和 Push 默认包含本地全部会话，服务器接收完整、不可变、SHA-256 验证的 Revision Tree。

目标是在不破坏完整 Revision 语义的前提下，引入 Git 式工作区与暂存选择：

    本地全部会话 = 工作区
    用户勾选的变化 = 暂存区
    远端完整树 + 暂存区变化 = 新完整 Revision

不允许将仅勾选的会话直接作为远端 Revision，因为未勾选会话会被误解释为删除。

### 2. 约束与兼容性

- 基准为当前 Codex Home、远端和命名空间对应 Tracking integratedHead。
- 首次 Push 没有基准时，本地全部会话为新增。
- 服务器不感知暂存区；选择只存在于桌面客户端。
- Codex 必须关闭后才能精确确认变更、创建快照、恢复或 Push。
- 选择快照和完整快照都必须保留对象验证、备份、Journal、SQLite 事务、回滚、Tracking CAS 和冲突处理。
- 旧快照保持可读，缺少范围字段时按完整快照解释。
- 不引入强制 Push、静默冲突覆盖或自动同步删除。

### 3. 分层边界

    React 选择弹窗
      → Tauri 命令与后台任务
      → sync-core 扫描、差异、暂存、快照、树合成
      → remote_sync Push/Pull/三方合并
      → HTTP Server 完整 Revision 与对象存储

职责：

- sync-core：纯 Rust 领域逻辑；不依赖 Tauri、React 或 HTTP。
- remote_sync：远端 Head、完整树下载、对象上传、CAS、Tracking 与冲突编排。
- Tauri：上下文解析、Lease、后台任务、进度和结果投影。
- React：展示与勾选；不计算语义哈希、不决定合并结果、不直接写 Codex 数据。

### 4. 基准、工作区与变更计划

新增纯领域类型：

    WorkspaceThreadState
    BaselineThreadState
    ChangeKind = Added | Modified | ArchiveChanged | Deleted | Unchanged
    ChangeCandidate
    ChangePlan
    StagedChangeSet

基准加载：

1. 从 Tracking 读取 integratedHead。
2. 优先从本地对象缓存读取 Revision Root 和线程描述。
3. 缓存缺失时按需下载基准 Revision 描述。
4. 首次 Push 使用空基准。

变更计划采用两阶段：

1. 快速候选阶段：比较 UUID、归档状态、路径、长度、修改时间和可信源对象索引。
2. 精确确认阶段：只规范化并比较候选变化 rollout 的语义哈希。

分类规则：

- 工作区有、基准无：Added。
- 两边都有且内容不同：Modified。
- 内容相同但 archived 不同：ArchiveChanged，UI 显示归档或恢复。
- 基准有、工作区无：Deleted。
- 完全相同：Unchanged。

删除候选保留基准里的标题、项目、原归档状态和线程摘要，因此本地文件已物理删除后仍可在暂存区展示。未勾选删除时，远端线程保持不变，下次仍继续显示为待删除。

普通扫描保持轻量。生成精确 ChangePlan 作为独立后台任务，仅在用户打开快照/Push 选择弹窗后执行；可信对象索引命中时复用对象，避免重新读取未变化 rollout。

### 5. 统一暂存选择弹窗

创建快照和 Push 都打开同一选择弹窗，复用现有会话浏览组件，并扩展 selection 模式：

    活动 / 归档
      项目 / 无项目
        会话
    待删除
      原活动 / 原归档
        原项目 / 原无项目
          已从本地删除的会话

功能：

- 会话、项目、活动/归档分类均有复选框。
- 父节点支持选中、未选中和半选状态。
- 支持全选变化、清空选择、全选当前层级和显示全部。
- 默认只显示 Added、Modified、ArchiveChanged、Deleted。
- 关闭仅变化开关后显示全部，Unchanged 默认不选中。
- 跨分页和返回上级保持勾选、页码和位置。
- 顶部显示已选新增、修改、归档/恢复、删除数量与预计上传大小。
- 选择模式只读，隐藏归档、恢复、删除工作区操作。
- 执行前重新验证所选 UUID 的本地指纹、归档状态、基准 Revision 和远端 Head；过期计划要求重新生成。

### 6. 快照格式与恢复

扩展本地快照 Manifest，并保持向后兼容：

    scope: full | selection
    base_revision_id: optional
    selected_changes: optional
    deleted_thread_ids: optional
    captured_local_fingerprints: optional

规则：

- 用户选择完整工作区且选择全部待删除变化时，生成 full 快照。
- 用户只选择部分变化时，生成 selection 快照。
- selection 快照保存选中的新增/修改线程对象及明确选择的删除意图。
- full 快照保留现有精确恢复、历史恢复和完整 Push 能力。

selection 快照恢复提供两种显式操作：

1. 增量恢复：仅应用所选新增、修改、状态变化和删除，保留其他本地会话。
2. 精确恢复：以选择集合替换本地线程集；确认框以危险样式说明未包含会话将丢失。

两种恢复均复用现有关闭检查、完整备份、Journal、事务验证和自动回滚。

### 7. 选择 Push 与完整树合成

选择 Push 的输入为 StagedChangeSet 或 selection 快照，输出始终是完整 Revision Tree：

    远端当前 Head 完整树
      + 已选新增
      + 已选修改
      + 已选归档状态变化
      - 已选删除
      = 新完整 Revision Tree

执行步骤：

1. 确认 Codex 已关闭，取得 Home 写 Lease 和仓库共享 Lease。
2. 精确确认暂存计划，构建 full 或 selection 快照。
3. 读取远端当前 Head 与 namespace epoch。
4. Head 等于 base_revision_id 时，加载远端完整树并应用选中变化。
5. Head 已变化时执行三方处理：
   - base：Tracking integratedHead。
   - local：用户已选暂存变化。
   - remote：当前远端 Head。
6. 同 UUID 的修改/修改或删除/修改进入现有冲突工作台；未选变化不参与合并。
7. 仅上传选中新增或修改会话需要的缺失对象。
8. 从合成的完整线程树构建 Revision Root，以 expectedHead CAS Commit。
9. 成功后原子更新 Tracking integratedHead 和活动命名空间绑定。
10. CAS 失败时重新读取 Head 并重新计划或进入冲突界面；不执行强制 Push。

### 8. 性能设计与优化

性能目标是保持普通扫描的当前轻量特性，并使“只选择少量变化”的快照或 Push 明显少于全量读取、规范化和上传。

#### 8.1 基准缓存

为当前“规范化 Codex Home、远端 ID、命名空间 ID、已整合 Head”建立可失效的基准描述缓存：

- Tracking 仍是基准 Revision 的权威指针，缓存不是新的同步真相。
- 缓存保存 Revision Root、线程 ID 到 ThreadRef 的映射，以及已加载线程描述的紧凑摘要。
- 打开暂存弹窗时，优先使用本地对象库和该缓存；只在对象缺失或已整合 Head 改变时下载远端数据。
- Push、Pull、命名空间切换、Tracking 修复和本地选择恢复完成后，使受影响缓存失效。
- 远端最新 Head 不在缓存中推断；真正 Push 前仍强制读取服务器 Head 和 epoch。

#### 8.2 只精确比较候选变化

普通扫描不得退化为全量 rollout 哈希：

1. Dashboard 扫描继续只读取 rollout 首条元数据和数据库摘要。
2. 使用现有可信源对象索引中的规范路径、长度、修改时间、线程 UUID 和对象引用，判断明显未变化的来源并直接复用。
3. 仅对新增、大小或修改时间变化、归档状态变化、索引缺失或索引损坏的会话读取完整 rollout 并做规范化与语义哈希。
4. 基准存在而本地缺失的删除项不读取本地 rollout；仅加载必要的基准摘要。
5. 精确确认放在变更计划后台任务和执行前复核阶段，不放入普通扫描路径。

当前可信索引以长度和修改时间作为受信任的本地来源指纹。为处理极端的“内容变化但长度和修改时间相同”场景，保留严格验证入口：显式验证时强制重新哈希所有候选或全部会话。

#### 8.3 远端完整树的按需合成

选择 Push 不复用当前全图下载路径：

- 首先只下载远端 Revision Root；Root 中的 ThreadRef 已足以保留未选择的会话引用。
- 对已选择新增或修改、待删除项和潜在冲突项，才按需加载线程描述。
- 未选择且未冲突的远端会话只复用其 ThreadRef，不下载 rollout、不规范化、不重传。
- 合成完整 Revision Tree 时遍历全部 ThreadRef 元数据是允许的；它的成本与会话数量线性相关，但不与 rollout 总字节数成正比。
- 远端 Head 改变时，按需加载 base、remote 和 selected local 的相关线程描述；仅在冲突工作台需要摘要或详情时进一步读取。

#### 8.4 只上传变化对象

- 选择快照只规范化和写入已选择新增、修改或状态变化的会话对象。
- 选择删除只记录删除意图，在最终完整树中移除 ThreadRef，不创建或上传删除对象。
- 延续现有缺失对象查询、流式上传、SHA-256 和长度校验、不可变安装和并发上传限制。
- 未变化、未选择和仅被保留的远端会话不产生 rollout 上传；最终 Revision Root 仅增加很小的完整引用清单。
- 当全部选择时，行为和当前全量快照或 Push 等价；首次建立基准或索引失效时允许接近全量成本。

#### 8.5 UI 分页与按需加载

- 继续使用每层 10 项分页；本地选择状态独立于分页与层级导航保存。
- 默认“仅显示变化”只渲染变化分组；关闭开关后才按当前层级分页渲染未变化会话。
- 待删除分组先由基准 Root 的线程 ID 差集生成；进入该项目或会话层时才读取对应基准线程摘要。
- 会话正文详情保持现有按需读取和分页，不参与 ChangePlan，也不在选择弹窗预取。
- 大量项目或线程时使用稳定 UUID 键、增量分组和后台任务进度，避免在主线程做语义计算。

性能验收：

- 普通扫描不读取完整 rollout 正文，也不计算全部语义哈希。
- 无变化的二次打开暂存弹窗不重新下载基准 Root 或重新读取未变化 rollout。
- 选择一个会话 Push 时，仅读取该候选会话和必要基准描述；未选择的远端会话不下载 rollout。
- 全选全部、首次 Push、严格验证和缓存失效可接近现有全量成本，但必须显示明确进度。

### 9. 后台任务与前端状态

新增任务类型：

    change-plan
    selection-snapshot
    selection-push
    selection-restore

任务进度应覆盖候选分析、精确确认、对象规范化、树合成、上传、CAS、恢复或回滚。执行期间禁用提交按钮，完成后刷新会话浏览、快照、Tracking 和同步结果。错误中不得包含令牌、API Key 或会话正文。

### 10. 分阶段实施

#### 阶段 A：领域模型与差异

在 sync-core 增加基准加载、ChangePlan、StagedChangeSet、选择集验证和完整树合成纯函数。先写新增、修改、归档、恢复、删除、未变化和首次 Push 的单元测试。

#### 阶段 B：选择快照与恢复

扩展 Manifest、对象写入、验证与恢复路径，实现 full/selection 范围、增量恢复、危险精确恢复、Journal 和回滚测试。

#### 阶段 C：选择 Push 与冲突

在 remote_sync 与 Tauri 命令层加入计划、选择快照和选择 Push 任务。复用现有上传、Tracking、Head CAS 和冲突编排，补充并发远端变更测试。

#### 阶段 D：暂存选择界面

将文件夹会话浏览抽成 browse/selection 模式，加入复选、半选、虚拟待删除分组、分页位置保留、变化过滤、统计、确认与任务状态。

#### 阶段 E：集成与回归

使用临时 Codex Home 覆盖 A/B 选择 Push、选择删除、选择修改、远端并发修改、选择恢复和重启恢复。最后运行完整项目验证。

### 11. 测试与验收

至少覆盖：

- 已推送且未变化的线程不在默认变化列表。
- 只选择 A 修改时，未选择的 B/C 保留在完整 Revision。
- 基准有、本地无的线程仅在选择删除后才从远端树移除。
- 多选、全选、半选和跨分页选择正确。
- selection 快照增量恢复保留其他会话；精确恢复移除未包含会话且可回滚。
- 远端 Head 变化时进入三方处理；冲突不静默覆盖。
- 可信对象索引命中时，不为未变化 rollout 重新哈希。
- 普通扫描不读取完整 rollout，二次打开暂存弹窗命中基准缓存。
- 选择单个会话 Push 时，仅请求远端 Root、必要线程描述和选择对象，不下载未选 rollout。
- 选择删除时不产生删除对象上传，最终 Revision 仅移除对应 ThreadRef。
- 取消、失败、重试不会留下错误 Tracking、临时对象或非终态 Journal。

最终验证：

    cargo fmt --all -- --check
    cargo test --workspace
    cargo check --workspace
    cargo clippy --workspace --all-targets -- -D warnings
    cd apps/desktop
    npm run check
    npm run build

### 12. 非目标

- 服务器端感知暂存区或选择快照。
- 强制 Push、自动删除远端会话、静默覆盖冲突。
- Codex 运行时创建可用于 Push 的精确快照。
- 将选择快照默认视为安全的完整恢复点。
