# 导航极简合并设计（面向使用者更易理解与上手）

- 日期：2026-08-07
- 范围：Tauri 桌面 UI（`apps/desktop`），仅前端渲染层重构
- 硬约束：**不修改任何逻辑功能**。所有 IPC 命令、确认弹窗流程、busy 互斥、Codex 关闭检查、任务状态处理、路由跳转语义均保持不变，仅调整页面渲染结构与入口位置。

## 背景与目标

当前界面有 7 个顶层导航项（概览、同步、会话、命名空间、快照与恢复、设置、高级工具），功能入口分散且有重复，新用户难以理解与上手。

目标：面向使用者将界面精简为 **4 个顶层页面**，功能零损失，让导航更清晰、首次上手更顺畅。

**设计原则：页面内容按"用户实际操作步骤"组织，而非按功能模块上下堆叠。** 每个页面应回答"用户此刻想做什么、下一步是什么"，把低频/维护性功能收进折叠或次级入口，不打断主流程。

## 顶层导航（方案 A：极简四页）

删除 3 个独立顶层入口，其功能分别并入其余页面：

| 保留的顶层页面 | 收纳的现有功能 | 说明 |
|---|---|---|
| **概览** `/overview` | （保留引导式欢迎页）当前状态 + 配置步骤 + 最近同步摘要 | 首次上手引导，已配置用户可直接跳到同步页 |
| **同步** `/sync` | `/history` 全部功能、冲突工作台、Provider 同步 | 用子标签隔离"动作"与"检视" |
| **会话** `/sessions` | （不变）本机会话扫描与警告 | 无改动 |
| **设置** `/settings` | `/namespaces`、`/advanced`（自动映射/项目路径/手动快照） | 高级工具收进折叠区 |

被删除的顶层入口：`/history`、`/namespaces`、`/advanced`。

### 导航栏改动（`AppShell.tsx`）

- `navigation` 数组由 7 项缩减为 4 项：概览、同步、会话、设置。
- `titles` 映射同步更新；移除 `/history`、`/namespaces`、`/advanced` 的顶层标题（其内容归属新页面后标题随之变化）。
- 侧边栏导航仅保留对应 4 个 `NavLink`。

## 同步页 `/sync`（步骤流组织）

同步页收纳 `/history` 全部功能，并**按用户操作步骤**从上到下组织，不使用并列子标签堆叠。页面回答"我现在想同步什么、下一步做什么"：

**① 同步上下文（常驻顶部）**：明确"当前从本机，同步到哪个远端命名空间"（Codex Home / 远端 / 命名空间）。这是所有操作的前提，用户先在此确认。

**② 同步方向（主操作区）**：两个清晰、互斥的主操作，各带一句"做什么"的说明——
- **推送到远端**：把本机新增/修改的会话传到服务器
- **从远端拉取**：把服务器上其他电脑的会话同步到本机

执行后的结果直接展示在本步下方。

**③ 冲突处理（按需出现）**：仅当 ② 遇到冲突时，就地进入解决流程（保留本地 / 保留远端 / 明确删除），逐条处理完再继续。

**④ 历史与恢复（次要，折叠）**：查看版本图谱、恢复到某版本、操作恢复点、回收站 / GC、存储统计。日常不常用，收进次级折叠入口（原 `/history` 完整工作台），不打断 ①②③ 主流程。四来源切换（本地 / 远端 / 操作恢复 / 回收站）与版本详情、语义恢复、回退 Head 等按钮原样搬移，不改逻辑。

要点：
- `/history` 路由整体并入此页；原版本详情、语义恢复、回退 Head 等按钮代码块不改逻辑，仅搬移位置。
- 冲突工作台目前和同步结果一起渲染在 `/sync`，归入 ③ 冲突步骤，仅在存在冲突时展示。
- `VersionGraphTable` 组件复用：② 方向步展示精简子集（`syncVersionRows`），④ 历史折叠展示全量（`localVersionRows`/`remoteVersionRows`）。不改组件内部逻辑。
- **Provider 同步**（本机会话切换到当前 provider）属于低频维护操作，**移出同步页**，收进设置页高级工具折叠区。

## 设置页 `/settings`（按配置优先级分组）

设置页按"配置优先级"分组（首次使用需先完成 ①，其余按需）：

| 分组 | 收纳功能 | 说明 |
|---|---|---|
| **使用前必配** | 本机存储（Codex Home、本地同步仓库）、远端服务器（配置名 / URL / Bearer Token、测试连接） | 首次使用的核心配置 |
| **组织会话** | 从 `/namespaces` 并入：命名空间列表、设为同步目标、创建/重命名 | 可选，按需使用 |
| **外观** | 主题选择 | 不变 |
| **高级工具**（折叠区） | 从 `/advanced` 并入：自动选择映射、项目路径（映射/迁移/清理）、**Provider 同步**、手动快照工具 | 默认收起，避免设置页过重 |

要点：
- `/namespaces`、`/advanced` 顶层入口删除，功能整体搬入设置页区块；不改变任何 IPC 调用与逻辑。
- 高级工具默认收起（`<details>` 折叠区），避免设置页过重。
- 现有 `/advanced/automatic`、`/advanced/projects` 的分段渲染逻辑改为设置页内子分区（倾向上下排列，不引入新标签）。
- 手动快照工具（当前实际不可达的 `snapshotTools`）收进高级工具折叠区，消除重复。

## 路由与代码组织

- 保留现有 `router.tsx`（HashRouter / Route / NavLink）机制，不改路由实现。
- 路由表（`SessionSyncApp.tsx` 中 `<Routes>`）重新组织为：
  - `/overview`、`/sync`、`/sessions`、`/settings`
  - `/` 与 `*` 仍重定向到 `/overview`
  - `/history`、`/namespaces`、`/advanced/*` 不再作为路由目标（可移除或保留内部兼容重定向，倾向直接移除并在代码中清理引用）
- 同步页内的步骤流（④ 历史折叠展开/收起）用本地 `useState` 管理，不新增路由，避免影响现有 hash 路由与 last-route 记忆逻辑。

## 错误处理与安全（保持不变）

- 所有写操作仍走现有 `start(...)` 路径，保留 `busy` 互斥与 Codex 运行检测。
- 所有确认弹窗（快照/导入/恢复/发布/回退/清理等）原样保留。
- 任务状态、进度轮询、结果面板均复用现有 `job` / `snapshot` / `syncReport` 等 state 与渲染代码，仅移动挂载位置。

- 更新/补充前端测试以匹配新导航与页面结构（如 `AppShell.test.tsx` 的导航项断言、`App.test.tsx` 的页面渲染断言）。
- 逻辑行为测试（若有依赖路由路径的）同步调整。

- 使用 `?preview=conflict`、`?preview=mapping` 开发预览做浏览器视觉回归，确认各功能入口在新位置可用。

## 不做的事（范围外）

- 不改 Rust 后端、IPC 命令边界、数据库、安全逻辑。
- 不改 `router.tsx` 的路由实现机制。
- 不引入新依赖、不改视觉主题/样式体系（仅必要的布局类，若需新增少量 CSS 类以支撑步骤流/折叠区则允许）。
